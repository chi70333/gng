# 00. Overview — 왜 재구축하는가

## 배경
- 기존 시스템: PHP + MySQL, 한 서버에서 Apache/PHP-FPM 직동작.
- 사용자 1만 명 이상이 동시 접속하면 응답 지연·간헐적 장애 발생.
- `/m/` 별도 모바일 페이지 구조로 코드 이중 관리 비용 큼.
- 인코딩이 `euc-kr` 로 굳어 있어 외부 연동/검색 엔진 도입 어려움.

## 재구축 목표 (우선순위)
1. **트래픽 안정성**: 동시접속 5만+ 견디기. ISR/CDN/Redis로 DB 부하 최소화.
2. **모바일 최적화**: 단일 반응형, Core Web Vitals 모바일 4G 기준 통과.
3. **API 호환**: 외부에서 호출 중인 기존 엔드포인트는 그대로 동작.
4. **운영성**: Vercel 배포로 인프라 운영 부담 감축, 모니터링 표준화.

## 비목표 (이번 단계에서 안 함)
- 디자인 전면 리뉴얼 (구조만 옮기고 추후 개선)
- 새로운 기능 추가
- 마이크로서비스화 (모놀리식 Next.js로 충분)

## 성공 기준
- 메인/목록/상세 LCP < 2.5s (모바일 4G).
- 동시접속 부하테스트(k6) 5만 RPS 환경에서 에러율 < 1%.
- 외부 API 호환성 100% (응답 스키마 동일).
- 기존 SEO URL 301 매핑 100%.
